## 2. Comparison method and result accounting

The primary compatibility reference is the pinned TypeScript release, not a rewritten specification. Private fixtures bind requests to explicit launch manifests, independent state/token files and known project/workspace identities. A server cannot be accepted merely because a listener responds. Tests compare both the MCP text envelope and structured data, error outcomes, null versus omitted values, arrays, byte bounds and relevant HTTP headers.

Dynamic values have field-specific validated bindings. The harness does not remove arbitrary IDs, timestamps, file hashes, audit metadata, errors or truncation counters to produce a pass. Expected error responses are passing contracts when both sides return the same outcome. Approved behavior changes are reported separately from unchanged passes. The original failed evidence remains retained after a fix and rerun.

Recorded read-only production traffic is used only for baseline observation and replay. Mutation workflows run on private fixtures. Historical work tests construct no coordinator, session issuer, sweeper or launcher; their source reference exposes only attested read methods over a disposable normalized archive. Go reads the same immutable evidence and never executes ready or blocked historical runs. For `work_status` text blocks containing JSON, the comparison decodes all values and permits only JSON object-key order and insignificant whitespace; ordinary strings, arrays, types, fields and envelope metadata remain exact.
